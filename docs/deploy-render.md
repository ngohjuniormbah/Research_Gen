# Deploy to Render (3 steps)

Render is the fastest path here because [`render.yaml`](../render.yaml) (a Blueprint)
describes the whole stack — **web + worker + Postgres + Redis** — and Render provisions it
for you. The web service runs database migrations on start, so there's no manual migration
step.

## Prerequisites
- The repo pushed to GitHub (this PR's branch, or `main` once merged).
- A free [Render](https://render.com) account.

## Step 1 — Create the Blueprint
1. Render Dashboard → **New +** → **Blueprint**.
2. Connect this GitHub repo and pick the branch. Render detects `render.yaml`.
3. Click **Apply**. Render creates: `litreview-db` (Postgres), `litreview-redis`,
   `litreview-web`, `litreview-worker`. `FERNET_KEY` and `EXPORT_URL_SECRET` are
   auto-generated and shared between web and worker.

> If Render labels Redis as **Key Value** and rejects `type: redis`, change that one line
> in `render.yaml` to `type: keyvalue` and re-apply. Everything else is unchanged.

## Step 2 — Set the frontend origin
In **litreview-web → Environment**, set the one value left blank on purpose:

```
CORS_ORIGINS = ["https://your-frontend.example.com"]
```

(Use `["*"]` only for a quick throwaway test — it disables credentialed CORS.)
Optionally set `SENTRY_DSN`. Save → Render redeploys.

## Step 3 — Seed test keys & smoke test
Open **litreview-web → Shell** and run:

```bash
python scripts/seed.py 3
```

Copy the 3 printed API keys (shown once). Then verify:

```bash
BASE=https://litreview-web-XXXX.onrender.com   # your web service URL
curl -s $BASE/healthz     # {"status":"ok"}
curl -s $BASE/readyz      # {"status":"ready","database":"ok"}
```

Run the "Getting started in 10 minutes" flow from
[`api-contract.md`](./api-contract.md) to confirm generate → poll → export end to end.

---

### Notes
- **Migrations** run automatically via the web service's start command
  (`alembic upgrade head && uvicorn …`). No separate step.
- **Free tier** sleeps after inactivity and gives limited Postgres/Redis — fine for a
  frontend integration environment. Bump the `plan:` fields in `render.yaml` for
  always-on staging.
- **Secrets** (`FERNET_KEY`, `EXPORT_URL_SECRET`) are generated by Render and shared to the
  worker via `fromService`. The app accepts any secret string for `FERNET_KEY` (it stretches
  a non-Fernet value into a valid key), so the auto-generated value just works.
- **Persistent files**: exported PDFs are stored on the web service's ephemeral disk by
  default. For durable storage add a Render Disk or point the S3/MinIO vars at object
  storage — but the signed-URL download flow works as-is for staging.
